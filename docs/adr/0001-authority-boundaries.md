# ADR 0001 — Authority boundaries in code

- **Status:** Accepted
- **Date:** 2026-09-21
- **Scope:** V0.1 and all later phases unless superseded

## Context

The master reference (Sections 2, 9, 12) requires that AI and strategy code
may propose, only deterministic code may size and permit, and only the
execution layer may mutate order state. A convention that relies on
components *choosing* not to overstep would be broken by the first careless
refactor.

## Decision

The boundaries are enforced structurally, not by convention:

1. `Strategy.evaluate` returns a `Signal`. `Signal` has no size field. A
   strategy receives a `FeatureSnapshot` and a read-only `PortfolioSnapshot`;
   it holds no reference to risk, execution or the ledger.
2. `HardRiskEngine.assess` is a pure function of signal, portfolio, market
   state and config. It returns a `RiskDecision` and has no reference to
   execution. It cannot place an order even by mistake.
3. `ExecutionSimulator.build_intent` is the **only** constructor of
   `OrderIntent`. It raises `RiskBypassError` for any `REJECT` or zero-size
   decision, and for `WAIT`. A reject therefore cannot become an order even if
   a caller forgets to check the verdict.
4. `PortfolioLedger` accepts `Fill`s only. It re-checks the accounting
   identity after every mark and raises `AccountingError` on violation.
5. Risk may always be given back: reducing/closing orders pass once data and
   system health are sane, even under kill switch or drawdown halt. Only
   *new* risk is blocked by those gates.

## Consequences

- Tests can assert the veto directly (`test_reject_cannot_become_an_order`).
- Adding an LLM agent later cannot grant it capital authority without editing
  `risk/` or `execution/`, which this ADR requires be preceded by a new ADR.
- Stop exits are generated by the engine from the position's stop, not from an
  `OrderIntent`. This is deliberate — a stop is a risk-engine commitment made at
  entry — and the traceability test exempts fills whose reason starts `STOP:`.
